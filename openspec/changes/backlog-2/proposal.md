## Why

Three analysis items can ship now. The weekly eval run cannot fetch the photo set: Commons answered HTTP 429 to 154 of 180 back-to-back downloads, so the run never reaches the eval and BL-49 never gets its clean runs (BL-52). The web flow and the eval run color sampling twice on every passing photo, because the photo check throws away the sample it already took (BL-40). And two analysis-eval scenarios are proven one level down or not at all, because the logic they describe sits inside run-only vitest files no unit test can reach (BL-17).

## What Changes

- **BL-52:** `fetchMissing` pauses between downloads and retries an HTTP 429 a few times, waiting for `Retry-After` (capped) or a backoff, before it counts the photo as failed. Other statuses still fail at once.
- **BL-40:** a passing photo check carries the traits it already sampled; `checkImage` and the eval pipeline use them instead of sampling again.
- **BL-17:** the body of `eval.run.ts` moves into a function a unit test can call with a stubbed fetch and extractor, and the paid vision run's tally moves into `evals/`; new unit tests prove "A photo cannot be had" at the run level and "A usable photo the model rejects".
